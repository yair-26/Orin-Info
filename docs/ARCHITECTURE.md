# ARCHITECTURE – ORIN INFO

תמצית. האפיון הטכנולוגי המלא (גרסה 1.1) הוא מסמך נפרד אצל המייסדים.

## זרימה
טלפון משתמש ← ספק טלפוניה ← חיבור אודיו בזמן אמת ← זיהוי דיבור (STT) ← מדיניות וסיווג ← מודל שפה עם כלי חיפוש ← בדיקת תשובה ← יצירת קול (TTS) ← חזרה לטלפון.
במקביל כל תור שיחה נרשם בלוג עם עלות וזמנים.

## מחסנית
- Python + FastAPI.
- מסגרת קול מוכנה: Pipecat או LiveKit Agents (הכרעה בשבוע 1, החלטה D-002).
- מסד נתונים: PostgreSQL. פיתוח מקומי ראשוני יכול להתבסס על SQLite דרך SQLAlchemy עד שבוע 3, והסכמה נשארת ניידת (החלטה D-004).
- סביבת פיתוח: WSL2 + Ubuntu על Windows 11, בלי Docker בהתחלה. Docker ו-VPS מגיעים בשבוע 3.

## רכיבים וממשקים (core/providers)
לכל רכיב ממשק אחד, כמה מימושים, ובחירה ב-config/providers.yaml:
- STT: קבלת אודיו, החזרת טקסט, ביטחון וזמן.
- TTS: קבלת טקסט, החזרת אודיו, זמן ותווים.
- LLM: קבלת הודעות וכלים, החזרת תשובה, טוקנים וזמן.
- Search: חיפוש ושליפת דף. תוצאה כוללת מקור ותאריך.
- Telephony: קבלת שיחה, זרם אודיו דו-כיווני.
לכל רכיב קיים מימוש mock שרץ בלי מפתח ובלי רשת.

## סוכן החיפוש (products/info)
מאגר תוצאות, חיפוש ושליפת דף. דפדפן אוטומטי רק בהמשך. תקרות על קריאות, זמן ועלות (config/limits.yaml). מידע מדפי אינטרנט נחשב מידע בלבד ולא הוראות. כל תשובה עם מחיר, טלפון או שעות כוללת מקור ותאריך, ולא מקריאים בלי אימות. בזמן חיפוש מושמע משפט מילוי.

## לוג תורות
כל תור הוא שורת JSON: call_id, turn_id, זמני STT, מודל וטוקנים, קריאות חיפוש, תווי TTS, זמני תגובה, סיווג ושגיאה. מחשבים עלות לפי config/pricing.yaml.
דוח (scripts/): עלות לדקה ולשיחה, ממוצע וחציון, לפי רכיב, ולפי שאלות עם חיפוש ובלי.

## מסד הנתונים (סכמה ניידת)
- calls: call_id, started_at, ended_at, status, total_cost, מזהה משתמש פנימי (hash, לא מספר טלפון).
- turns: turn_id, call_id, זמנים לפי רכיב, טוקנים, תווים, קריאות חיפוש, עלות לפי רכיב, שגיאה.
- cost_events: פירוט עלות לפי רכיב, אם צריך.
- סכמה מוכנה בלבד, לא בשימוש לוגי עד החלטה D-003: users, call_summaries, memory_facts (עם מקור, תאריך ואפשרות מחיקה), embeddings (pgvector, ב-Postgres בלבד).
- תוכן שיחה: נשמר רק בהסכמת מדיניות שמירה (פתוח). אודיו לא נשמר כברירת מחדל.

## דשבורד (admin/)
רכיב נפרד שמתקשר עם השרת דרך API בלבד, בלי גישה למסד הנתונים ובלי מפתחות ספקים. החוזה ב-docs/api-contracts.md.

## חלוקת שליטה בספקים
ספק מוחלף בשינוי הגדרה. הרצה עצמית של רכיב (למשל STT) נשקלת רק אחרי שיש נתוני עלות אמיתיים ובוחנים חישוב כדאיות (החלטה D-005).
