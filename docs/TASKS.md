# TASKS – משימות

פורמט כרטיס: אחראי, תיאור, תוצאה מצופה, תנאי הצלחה, דרך בדיקה, תלויות, הערכת זמן (שעות, לא מחייב).
אחראי "CC" = Claude Code (ובן אדם מאשר). "אדם" = לא ניתן לבצע ב-Claude Code.

## שלב א: בסיס שניתן להריץ בלי מפתחות (סשן ראשון ב-Claude Code)

### T-01 שלד פרויקט
- אחראי: CC
- תיאור: Python 3.11+, FastAPI עם endpoint /health, pyproject, ניהול תלויות, טעינת config ו-.env.
- תוצאה: השרת עולה מקומית. README מעודכן בהוראות הרצה.
- תנאי הצלחה: GET /health מחזיר 200. בדיקה אוטומטית עוברת.
- דרך בדיקה: הרצת השרת והבדיקה, צירוף הפלט.
- תלויות: אין. זמן: 1–2 שעות.

### T-02 ממשקי ספקים וספקי דמה
- אחראי: CC
- תיאור: ממשקים ל-STT, TTS, LLM, Search, Telephony ב-core/providers, מימוש mock לכל אחד, ובחירה ב-config/providers.yaml.
- תוצאה: אפשר להריץ שיחה מדומה מקצה לקצה בלי רשת.
- תנאי הצלחה: החלפת ספק בשינוי הגדרה בלבד. בדיקות לכל mock.
- תלויות: T-01. זמן: 3–4 שעות.

### T-03 תקרות והגדרות
- אחראי: CC
- תיאור: טעינה ואכיפה של config/limits.yaml (משך שיחה, קריאות כלים).
- תנאי הצלחה: בדיקה שחריגה מתקרה עוצרת את השיחה.
- תלויות: T-02. זמן: 1–2 שעות.

### T-04 מסד נתונים וסכמה
- אחראי: CC
- תיאור: SQLAlchemy + migrations. טבלאות calls, turns, cost_events. טבלאות הזיכרון (users, call_summaries, memory_facts) כסכמה בלבד, לא בשימוש, לפי D-003.
- תנאי הצלחה: migration עולה ויורד נקי. אין מספר טלפון ולא תוכן שיחה בטבלאות חוזה ה-API.
- תלויות: T-01, החלטה D-004. זמן: 3 שעות.

### T-05 לוג תורות וחישוב עלות
- אחראי: CC
- תיאור: כל תור נרשם כשורת JSON ובמסד הנתונים עם השדות באפיון. עלות מחושבת לפי config/pricing.yaml. אם מחיר חסר (null), העלות מסומנת "לא ידועה" ולא 0.
- תנאי הצלחה: בדיקה עם מחירי בדיקה פיקטיביים שמסומנים ככאלה.
- תלויות: T-02, T-04. זמן: 3 שעות.

### T-06 שיחת טקסט עם מודל שפה
- אחראי: CC לקוד, אדם למפתח
- תיאור: מימוש LLM אחד אמיתי מאחורי הממשק (הספק נבחר על ידי אדם), ושיחת טקסט בעברית בטרמינל עם מדידת זמן, טוקנים ועלות.
- תנאי הצלחה: שיחה של 5 תורות עם לוג מלא. עובד גם עם mock.
- תלויות: T-05, מפתח LLM. זמן: 2–3 שעות.

### T-07 דוח עלות
- אחראי: CC
- תיאור: scripts/cost_report: עלות לדקה ולשיחה, ממוצע וחציון, לפי רכיב, לפי שאלות עם חיפוש ובלי.
- תנאי הצלחה: רץ על לוג לדוגמה ומפיק דוח.
- תלויות: T-05. זמן: 2 שעות.

### T-08 תשתית מבחן 50 שאלות
- אחראי: CC לתשתית, אדם לשאלות
- תיאור: scripts/eval: קובץ CSV של שאלות (שאלה, סוג, תשובה נכונה, מקור), הרצה על כמה מודלים, ומדידת נכונות, מהירות, אורך ועלות.
- תנאי הצלחה: רץ על 5 שאלות לדוגמה עם mock.
- תלויות: T-06. זמן: 3 שעות.

### T-09 נתוני דמה ללוג לדוגמה
- אחראי: CC
- תיאור: קובץ לוג לדוגמה, ו-admin/mock-data לפי docs/api-contracts.md, כדי שיאיר יתחיל בדשבורד.
- תנאי הצלחה: הנתונים תואמים לחוזה.
- תלויות: T-05. זמן: 1–2 שעות.

### T-18 הכנת פריסה ל-staging
- אחראי: CC להכנה, אדם להרשמות ולאישור
- תיאור: קובץ הגדרת פריסה (למשל render.yaml), קריאת DATABASE_URL ממשתנה סביבה, endpoint /health, סקריפט migrations וסקריפט scripts/seed לנתוני בדיקה, והוראות ב-docs/DEPLOYMENT.md.
- תוצאה: כתובת באוויר שמחזירה /health ו-/calls מנתוני בדיקה.
- תנאי הצלחה: שני המייסדים פותחים את הכתובת. migration רץ נקי במסד המשותף. אין סודות ב-Git.
- דרך בדיקה: פריסה מ-main, קריאה ל-/health וקריאה ל-/calls, והרצת seed פעמיים (לא מכפיל נתונים).
- תלויות: T-01, T-04, T-09, החלטה D-007, חשבונות ספקים (אדם). זמן: 3–4 שעות.
