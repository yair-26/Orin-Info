# DEPLOYMENT – סביבת staging חינמית ועבודה של שני אנשים במקביל

עודכן: 22.11.2026. תנאי החינם של ספקים משתנים. לפני הרשמה, בודקים את דף התמחור של הספק (אין להסתמך על המסמך הזה). חבילות חינמיות שהיו קיימות נעלמו בשנים האחרונות.

## מטרה
סביבה אחת באוויר, שגם אביאל וגם יאיר רואים ומעדכנים: ה-API, הדשבורד ונתוני בדיקה. לא לשיחות אמיתיות בקול.

## מה סביבה חינמית לא מתאימה לו
- שיחות טלפון בזמן אמת: שירותים חינמיים נרדמים אחרי חוסר פעילות ולוקח בערך דקה להתעורר. שיחה קולית דורשת שרת ער 24/7 (VPS קטן בתשלום, שבוע 3 בתוכנית).
- נתוני משתמשים אמיתיים: אין עדיין מדיניות פרטיות, שמירה וייעוץ משפטי. בסביבה החינמית רק נתוני דמה ונתוני בדיקה של המייסדים.

## ההרכב המוצע (D-007)
| צורך | פתרון | הערות |
|---|---|---|
| קוד ושיתוף | GitHub, Repository פרטי | ענף לכל משימה, Pull Request, אישור אנושי |
| שרת API ודשבורד באוויר | שירות Web חינמי (מועמד: Render, עם render.yaml) | נפרס אוטומטית מ-main. נרדם, מתעורר בערך דקה |
| נתונים משותפים | Postgres חינמי (מועמד: Neon) | משותף לשניים. נרדם אחרי 5 דקות ללא פעילות ומתעורר מהר. מוגבל בגודל |
| פיתוח אישי | כל אחד מריץ מקומית ב-WSL | כל אחד עם ענף Git וענף מסד נתונים משלו |

הערות:
- אין להניח שדיסק של שירות חינמי נשמר. לכן מסד נתונים חיצוני משותף, ולא SQLite (עדכון להחלטה D-004).
- סודות (מפתחות, DATABASE_URL) מוגדרים בלוח הבקרה של הספק, לא ב-Git.
- תקרות הוצאה בכל חשבון ספק (LLM, STT, TTS) מוגדרות לפני חיבור, גם בסביבה חינמית.

## עבודה במקביל, שני אנשים
- כל אחד עובד בענף שלו ולא נוגע בקבצים של השני (core של אביאל, admin של יאיר).
- שינויי סכמה במסד הנתונים רק דרך migrations שנכנסים ב-Pull Request. אף אחד לא משנה טבלאות ידנית במסד המשותף.
- ענף מסד נתונים לכל אחד לבדיקות (ב-Neon זה ענף copy-on-write), כדי לא לשבור את הנתונים של השני.
- עדכון נתונים: סקריפט seed אחד (scripts/seed) שמזין נתוני בדיקה. נתוני הדמה נשמרים ב-admin/mock-data ובגרסה ב-Git.

## מה בן אדם עושה (Claude Code לא יכול)
1. פתיחת חשבון GitHub משותף ו-Repository פרטי, והוספת שני המייסדים.
2. הרשמה לשירות האירוח ולמסד הנתונים (אחרי בדיקת תנאים עדכניים), חיבור ה-Repository.
3. הגדרת משתני סביבה בלוח הבקרה.
4. אישור הפריסה הראשונה ובדיקה שהכתובת עובדת.

## אימות תנאים (22.11.2026, מדפי הספקים)
- Render, שירות Web חינמי: נרדם אחרי 15 דקות בלי תנאי תעבורה ולוקח כדקה להתעורר; 750 שעות חינם בחודש; הדיסק זמני (קבצים נמחקים בכל פריסה או שינה). מקור: render.com/docs/free.
- Render Postgres חינמי: פג תוקף 30 יום אחרי היצירה (לפי התיעוד הרשמי; מאמר צד שלישי כתב 90 יום, לא להסתמך עליו). לכן לא מתאים כמסד משותף ארוך טווח.
- Neon, תוכנית Free: קבועה ולא ניסיון, בלי כרטיס אשראי; 1 GB אחסון לפרויקט ו-100 שעות CU בחודש; נרדם אחרי 5 דקות; 10 ענפים לפרויקט. מקור: neon.com/faqs/free-plan-limits-and-quotas (עודכן 1.10.2026). דפים ישנים באתר מציגים מספרים אחרים, לכן לבדוק שוב בהרשמה.

## מצב נוכחי: staging על נתוני דמה, בלי מסד נתונים
`core/app.py` מגיש /health, /calls, /calls/{id}, /summary מתוך `admin/mock-data/sample_log.jsonl` (פיקטיבי). אין מסד נתונים עד הכרעת D-004, ולכן אין עדיין עדכון נתונים בזמן ריצה: עדכון נתוני הדמה נעשה ב-`python3 -m scripts.make_mock_data` ו-commit. פריסה: Render, New > Blueprint, בחירת ה-Repository (קורא את render.yaml).

נבדק מקומית ב-22.11.2026: השרת עלה ב-uvicorn וכל ארבע הנקודות החזירו תשובה תקינה (curl).
הרצה על Render טרם בוצעה. הגדרת GitHub המשותף: `docs/GITHUB_SETUP.md`.
